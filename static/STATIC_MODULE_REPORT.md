# 餐厅打饭仿真系统 - Static 资源模块项目总结报告

## 一、文件夹整体概述

### 1.1 功能定位

`static` 文件夹是"餐厅打饭仿真系统"的前端资源核心模块，承载了该系统全部的前端静态资源，包括 HTML 页面结构、CSS 样式体系、JavaScript 业务逻辑及第三方依赖库。该系统是一个基于 Web 的餐厅运营仿真平台，通过模拟餐厅打饭场景中的排队、就餐等流程，帮助运营者分析资源配置合理性、识别系统瓶颈并提供数据驱动的优化建议。

### 1.2 与项目其他模块的关联性

- **后端服务（Flask）**：通过 `app.py` 提供 RESTful API 接口（`/api/start-simulation`、`/api/end-simulation`），前端通过 Fetch API 与后端进行数据交互
- **实时通信（Socket.IO）**：后端通过 Socket.IO 推送仿真过程中的实时数据（各窗口排队人数、桌子占用状态），前端接收后动态更新图表
- **AI 分析服务**：前端直接调用大模型 API（如阿里云 DashScope），将仿真结果数据发送给 AI 进行深度分析并生成优化建议报告

### 1.3 核心应用场景

- 餐厅运营优化：评估窗口数量、桌子数量配置是否合理
- 排队论教学演示：可视化展示排队系统的动态变化过程
- 资源配置决策：基于仿真数据提供科学的资源调整建议
- 用户体验评估：综合评估排队等待时间和就餐等待时间

## 三、技术实现分析

### 3.1 技术栈概览

| 技术 | 版本/来源 | 用途 |
|------|-----------|------|
| **HTML5** | 原生 | 页面结构，语义化标签（`<aside>`、`<main>`） |
| **CSS3** | 原生 | 样式体系，CSS 变量（Custom Properties）、渐变、Flexbox 布局 |
| **JavaScript (ES6+)** | 原生 + ES Modules | 业务逻辑，模块化开发（`import/export`） |
| **ECharts** | 5.4.3 (CDN) | 数据可视化：柱状图、饼图、折线图 |
| **Socket.IO** | 4.7.2 (CDN) | 实时双向通信，接收仿真实时数据 |
| **Marked.js** | CDN | Markdown 解析渲染，用于 AI 分析结果展示 |
| **Fetch API** | 原生 | HTTP 请求，与后端 API 交互 |
| **localStorage** | Web API | 主题偏好、AI 配置持久化存储 |

### 3.2 关键实现逻辑

#### 3.2.1 模块化架构

系统采用 ES Modules 模块化设计，各模块职责清晰：

```
config.js (环境配置)
    ↓
api.js (API 封装) ←── index.js (核心逻辑) ←── socket.js (实时通信)
    ↓                                              ↓
ai.js (AI 分析)                              图表渲染
```

- **config.js**：导出 `ENV` 对象，包含 `baseURL`、`socketURL`、`requestTimeout` 等配置项，支持开发/生产环境切换
- **api.js**：封装 `fetchPost` 函数，实现超时控制（`Promise.race`）、JSON 格式校验、错误统一处理
- **socket.js**：建立 Socket.IO 连接，监听 `simulation_data` 事件，调用全局渲染函数更新图表
- **index.js**：核心控制器，负责 DOM 元素初始化、ECharts 图表管理、仿真流程控制、事件绑定
- **ai.js**：AI 分析模块，管理 AI 配置（localStorage 持久化）、连通性测试、API 调用、Markdown 渲染
- **theme.js**：主题管理器，动态创建切换器 UI，管理主题切换逻辑

#### 3.2.2 主题系统实现

主题系统基于 CSS 变量（Custom Properties）实现，核心机制如下：

1. **变量定义**：每个主题 CSS 文件通过 `:root[class~="theme-xxx"]` 选择器定义一组 CSS 变量
2. **变量分类**：
   - 品牌色系：`--theme-primary`、`--theme-primary-light/dark/pale`
   - 功能色：`--theme-success`、`--theme-error`、`--theme-warning`、`--theme-info`
   - 图表色系：`--chart-series-1` ~ `--chart-series-6`（6 阶渐变）
   - 中性色：`--text-*`、`--bg-*`、`--border-*`、`--shadow-*`
3. **主题切换**：通过修改 `<html>` 元素的 class 实现主题切换，同时更新 `<link>` 标签的 `href`
4. **持久化**：使用 `localStorage` 保存用户主题偏好，页面加载时自动恢复

#### 3.2.3 图表渲染优化

系统采用 `requestAnimationFrame` 实现合帧渲染优化：

```javascript
// 渲染状态管理
renderState: {
    frameId: 0,
    pending: {
        windowBar: false,
        tablePie: false,
        windowLine: false,
        tableLine: false
    }
}
```

- **更新流程**：数据更新 → 标记 pending → `requestAnimationFrame` → 批量渲染
- **优势**：避免高频数据推送导致的重复渲染，提升性能
- **图表类型**：
  - 窗口柱状图：展示各窗口当前等待人数
  - 桌子饼图：展示桌子占用/剩余比例
  - 窗口折线图：展示各窗口排队人数随时间变化趋势
  - 桌子折线图：展示桌子占用/剩余数量随时间变化趋势

#### 3.2.4 实时通信机制

```
后端 Flask + Socket.IO
    ↓ (推送 simulation_data 事件)
socket.js 接收数据
    ↓ (调用全局函数)
index.js 更新图表数据缓存
    ↓ (requestAnimationFrame)
ECharts 渲染更新
```

- **连接配置**：强制使用 `polling` 传输方式，开启 `withCredentials` 携带 Cookie
- **重连机制**：自动重连（最多 5 次，间隔 1 秒）
- **数据校验**：接收数据时进行严格类型校验，防止非法数据导致图表崩溃

#### 3.2.5 AI 分析流程

```
仿真结束 → 收集仿真数据 → 构建 Prompt → 调用大模型 API → 接收 Markdown 响应 → Marked.js 渲染
```

- **配置管理**：API 地址、API Key、模型名称、提示词均支持自定义，配置保存至 `localStorage`
- **提示词模式**：支持"默认"和"自定义"两种模式，默认模式加载内置的专业分析 Prompt
- **连通性测试**：提供测试按钮，验证 API 配置是否正确
- **流式响应**：支持流式接收 AI 响应，实时显示分析进度

## 四、功能模块详解

### 4.1 仿真参数配置模块

**功能描述**：用户通过侧边栏表单输入仿真参数，包括：
- 平均用餐时间（分钟）
- 平均打饭时间（秒/人）
- 每分钟最大进入人数
- 窗口数量
- 桌子数量

**实现方式**：
- HTML 表单元素，带 `min`、`step`、`required` 等原生校验
- JavaScript 读取表单数据，进行二次校验（非负数、窗口数≥1、桌子数≥1）
- 校验失败时通过提示框显示错误信息

### 4.2 AI 配置模块

**功能描述**：配置大模型 API 连接信息，支持：
- API 接口地址配置
- API Key 配置
- 模型名称配置
- 提示词模式切换（默认/自定义）
- 连通性测试

**实现方式**：
- 配置项通过 `localStorage` 持久化存储（Key: `simulation_ai_config`）
- 默认模式加载内置的专业分析 Prompt（约 200 行），包含角色定位、任务目标、分析步骤、输出格式等
- 连通性测试发送简短测试消息，验证 API 连接状态
- 支持多种错误状态处理（401、403、404、429、超时等）

### 4.3 仿真控制模块

**功能描述**：控制仿真生命周期，包括：
- 启动仿真：提交参数到后端，建立 Socket 绑定
- 结束仿真：请求后端生成结果，接收趋势数据和评价

**实现方式**：
- **启动流程**：
  1. 校验表单参数
  2. 检查 Socket 连接状态
  3. 调用 `/api/start-simulation` 接口
  4. 接收 `session_id`，通过 Socket 发送 `bind_session` 事件
  5. 重置图表数据，启用"结束仿真"按钮
- **结束流程**：
  1. 调用 `/api/end-simulation` 接口
  2. 接收窗口排队趋势、桌子占用趋势数据
  3. 更新折线图展示
  4. 显示评价结果（窗口排队体验、桌子占用体验）
  5. 自动触发 AI 分析

### 4.4 实时数据展示模块

**功能描述**：仿真运行过程中，实时展示：
- 各窗口当前等待人数（柱状图）
- 桌子占用/剩余比例（饼图）

**实现方式**：
- Socket.IO 接收 `simulation_data` 事件
- 数据校验后调用全局渲染函数（`updateWindowBarChart`、`updateTablePieChart`）
- 数据缓存至 `state.chartData`，通过 `requestAnimationFrame` 合帧渲染
- 柱状图颜色根据排队人数动态变化（≥20 人显示警告色）

### 4.5 仿真结果分析模块

**功能描述**：仿真结束后展示：
- 各窗口排队人数变化趋势（多系列折线图）
- 桌子占用/剩余数量变化趋势（双系列折线图）
- 系统评价（窗口排队体验、桌子占用体验）

**实现方式**：
- 后端返回 `window_trend` 和 `table_trend` 数组
- 折线图支持动态系列数量（根据窗口数自动生成）
- 使用 `lttb` 采样算法优化大数据量渲染
- 评价结果通过 CSS 类名切换样式（`eval--good` / `eval--bad`）

### 4.6 AI 分析结果模块

**功能描述**：对仿真数据进行深度分析，生成结构化报告：
- 仿真参数配置分析
- 窗口排队统计分析
- 桌子占用统计分析
- 系统关联性分析
- 优化建议与方案预测

**实现方式**：
- 构建包含仿真参数和趋势数据的 JSON 请求体
- 调用大模型 API（OpenAI 兼容格式）
- 接收 Markdown 格式响应
- 使用 `marked.js` 渲染为 HTML
- 支持完整的 Markdown 语法（标题、表格、代码块、引用、列表等）

### 4.7 主题切换模块

**功能描述**：支持 4 种预设主题切换：
- 莫兰迪蓝（默认）
- 清新薄荷绿
- 薰衣草紫
- 珊瑚橙

**实现方式**：
- 动态创建主题切换器 UI（固定定位右上角）
- 点击按钮展开/收起主题列表
- 选择主题后修改 `<html>` 元素的 class
- 更新 `<link>` 标签的 `href` 加载对应 CSS
- 保存主题偏好至 `localStorage`
- 触发 `themeChange` 自定义事件，通知图表更新颜色

## 五、潜在优化点与建议

### 5.1 代码结构优化

| 优化项 | 当前状态 | 建议方案 |
|--------|----------|----------|
| **文档重复** | `THEME_GUIDE.md` 在根目录和 `css/` 目录各有一份 | 合并为一份，保留根目录版本 |
| **硬编码 URL** | `socket.js` 中硬编码 `http://localhost:5000` | 统一从 `config.js` 的 `ENV.socketURL` 读取 |
| **全局变量暴露** | `index.js` 通过 `window.xxx` 暴露多个函数 | 考虑使用事件总线或模块间通信机制 |
| **CSS 注释引用** | `base.css` 中大量注释"已迁移至 simulation.css" | 清理冗余注释，保持代码整洁 |

### 5.2 性能优化

| 优化项 | 影响 | 建议方案 |
|--------|------|----------|
| **第三方库体积** | `echarts.min.js` 约 1MB，`socket_io.js` 约 100KB | 考虑按需引入 ECharts 模块，或使用 CDN 加载 |
| **图表初始化** | 页面加载时同时初始化 4 个图表 | 考虑懒加载，仅在图表进入视口时初始化 |
| **主题 CSS 加载** | 切换主题时动态加载 CSS 文件 | 预加载所有主题 CSS，或使用 CSS-in-JS 方案 |
| **AI Prompt 体积** | 默认 Prompt 约 200 行，每次请求都发送 | 考虑后端缓存 Prompt，前端仅发送数据 |

### 5.3 功能增强

| 增强项 | 描述 | 优先级 |
|--------|------|--------|
| **仿真暂停/恢复** | 当前仅支持启动和结束，缺少暂停功能 | 中 |
| **仿真速度控制** | 支持调整仿真运行速度 | 低 |
| **数据导出** | 支持导出仿真结果为 CSV/JSON | 中 |
| **历史记录** | 保存历史仿真记录，支持对比分析 | 低 |
| **移动端适配** | 当前响应式适配较为基础 | 中 |
| **国际化** | 支持多语言切换 | 低 |
| **错误边界** | 增加全局错误捕获和友好提示 | 高 |

### 5.4 安全性建议

| 安全项 | 风险 | 建议方案 |
|--------|------|----------|
| **API Key 存储** | API Key 明文存储在 `localStorage` | 考虑加密存储或使用后端代理 |
| **CORS 配置** | Socket.IO 使用 `polling` 模式，可能存在跨域风险 | 确保后端正确配置 CORS |
| **输入校验** | 前端校验可被绕过 | 后端需进行二次校验 |
| **XSS 防护** | AI 分析结果通过 `innerHTML` 渲染 | 使用 `DOMPurify` 等库进行 HTML 净化 |

## 六、使用说明与注意事项

### 6.1 环境准备

1. **后端服务**：确保 Flask 后端服务已启动（默认端口 5000）
2. **浏览器要求**：支持 ES6+ 语法、Fetch API、Promise、CSS 变量
3. **网络要求**：可访问后端 API 和大模型 API 服务

### 6.2 启动步骤

1. 将 `static` 文件夹放置于 Flask 项目的静态资源目录
2. 启动 Flask 服务：`python app.py`
3. 浏览器访问：`http://127.0.0.1:5000/static/html/simulation.html`
4. 或直接使用 Python 内置服务器：`cd static && python -m http.server 8080`

### 6.3 使用流程

1. **配置仿真参数**：在侧边栏输入用餐时间、打饭时间、最大进入人数、窗口数、桌子数
2. **配置 AI（可选）**：输入 API 地址、API Key、模型名称，点击"测试连通性"验证
3. **启动仿真**：点击"启动仿真"按钮，观察实时图表变化
4. **结束仿真**：点击"结束仿真"按钮，查看结果分析和 AI 报告
5. **切换主题**：点击右上角主题切换器，选择喜欢的主题

### 6.4 注意事项

- **API Key 安全**：API Key 存储在浏览器本地存储中，请勿在公共电脑上使用
- **仿真参数合理性**：窗口数和桌子数至少为 1，其他参数不能为负数
- **网络稳定性**：仿真过程中请保持网络连接稳定，避免 Socket 断开
- **AI 分析耗时**：AI 分析可能需要数秒至数十秒，请耐心等待
- **浏览器兼容性**：推荐使用 Chrome、Edge、Firefox 等现代浏览器
- **主题切换延迟**：切换主题后图表颜色更新可能有短暂延迟（约 50ms）

### 6.5 常见问题排查

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| Socket 连接失败 | 后端服务未启动或端口不匹配 | 检查 Flask 服务是否运行，端口是否为 5000 |
| 仿真启动失败 | 参数校验未通过或后端接口异常 | 检查输入参数，查看浏览器控制台错误信息 |
| AI 分析失败 | API 配置错误或网络连接问题 | 点击"测试连通性"验证配置，检查 API Key 是否有效 |

## 1. 我们做了什么（概述）

前端是用户能看到的全部界面。用户打开浏览器，看到的是一个**侧边栏 + 主面板**的布局：

- **左侧边栏**：填写仿真参数（用餐时间、打饭时间、窗口数、桌子数等），点击"启动仿真"或"结束仿真"
- **右侧主面板**：上面是 4 个 KPI 指标卡片，下面是 4 张 ECharts 图表（柱状图、饼图、两条折线图）
- **底部 AI 分析区**：仿真结束后可以点击"AI 分析"，让 AI 给出优化建议

整个页面的核心体验是：**用户点击启动 → 图表每秒实时更新 → 点击停止 → 显示评价结果和趋势图**。

## 2. 前端用到了哪些技术

### 2.1 基础三件套

| 技术 | 文件类型 | 作用 |
|------|----------|------|
| HTML | `simulation.html` | 页面骨架，定义所有 DOM 元素的结构 |
| CSS | `base.css` + 5 个主题 CSS + `simulation.css` | 样式和主题配色 |
| JavaScript | 8 个 JS 文件（下面详述） | 所有交互逻辑、图表、通信 |

### 2.2 外部库（通过 CDN 加载）

这些库在 `simulation.html` 的 `<script>` 标签中引入，不需要手动下载：

| 库名 | 版本 | 作用 | 如果不加载会怎样 |
|------|------|------|-----------------|
| **ECharts** | 5.4.3 | 绘制柱状图、饼图、折线图 | 页面报错，图表区空白 |
| **Socket.IO Client** | 4.7.2 | 接收后端推送的实时数据 | 实时数据收不到，图表不更新 |
| **GSAP** | 3.12.5 | 数字滚动、侧边栏弹性动画、结果弹入 | 动画效果消失，但功能正常（有 CSS fallback） |
| **ScrollTrigger** | 3.12.5 | 滚动触发动画（GSAP 插件） | 滚动动画失效 |
| **tsParticles** | 2.12.0 | 背景粒子动画 | 背景变为纯色 |
| **marked.js** | - | 把 AI 返回的 Markdown 文本渲染成 HTML | AI 分析结果显示为纯文本 |

### 2.3 为什么选这些技术

- **ECharts**：国产开源，中文文档好，柱状图/饼图/折线图开箱即用
- **Socket.IO**：自动处理 WebSocket 连接/重连/降级，比裸 WebSocket 好用得多
- **GSAP**：业界最强的 JS 动画库，性能好、API 简洁
- **marked.js**：轻量级 Markdown 渲染器，9KB 大小，够用

## 3. 前端代码是怎么组织的

前端共有 8 个 JS 文件，放在 `static/js/` 下。它们通过 **ES6 模块**（`import`/`export`）互相引用：

```
config.js          ← 最底层：定义 URL、超时等常量
   ↓
api.js             ← 封装 HTTP POST 请求（调 config.js 的 URL）
socket.js          ← 管理 Socket.IO 连接（调 config.js 的 socketURL）
   ↓
index.js           ← 核心大脑（调 api.js 发请求、监听 socket.js 的事件）
ai.js              ← AI 分析模块（调 api.js 或后端代理）
enhance.js         ← 工具箱（Toast、音效、表单校验等）
theme.js           ← 主题管理器
animations.js      ← GSAP 动画引擎（特殊的 IIFE 模块）
```

### 3.1 每个文件干什么

| 文件 | 一句话总结 | 谁调用它 |
|------|-----------|----------|
| `config.js` | 定义 `baseURL`、`socketURL`、超时时间、移动端断点 | 所有其他模块 |
| `api.js` | 封装 `fetch()` 发 POST 请求，带超时控制 | `index.js`、`ai.js` |
| `socket.js` | 连接 Socket.IO 服务器，接收实时数据，转成 CustomEvent 发出去 | `index.js` 监听它的事件 |
| `index.js` | **最大的文件**：初始化图表、控制仿真启停、更新数据、计算 KPI | 页面加载时自动执行 |
| `ai.js` | 管理 AI 配置（存 localStorage）、调用 AI API、渲染 Markdown 结果 | `index.js` 初始化时调用 |
| `enhance.js` | Toast 通知、音效播放、涟漪效果、右键菜单、表单校验 | `index.js` |
| `theme.js` | 5 套主题的切换逻辑，发 `themeChange` 事件通知图表变色 | 用户点击主题按钮 |
| `animations.js` | **唯一不用 ES6 模块的文件**，挂载到 `window.Animations` 全局对象 | `index.js`、`enhance.js` 直接调用 `Animations.xxx()` |

### 3.2 特殊说明：为什么 animations.js 不用 ES6 模块

`animations.js` 使用 **IIFE（立即执行函数）** 模式，写成 `(function() { ... })()`，把 `Animations` 对象挂到 `window` 上。原因是：
- GSAP 的 ScrollTrigger 插件注册需要全局 `gsap` 对象
- 动画系统需要被多处调用，全局对象更方便
- 如果 GSAP 没加载，所有动画自动降级为 CSS transition，不会报错

## 4. 前端和后端怎么通信

前端和后端通过 **两种通道** 通信：

### 4.1 HTTP 请求（一问一答）

前端发一个请求，后端处理完返回结果。适用于**非实时**的操作：

```
前端 index.js                    后端 app.py
    │                               │
    │── POST /api/start-simulation──→  启动仿真线程
    │←── {success: true, session_id}──│
    │                               │
    │── POST /api/end-simulation───→  停止仿真 + 查数据库
    │←── {趋势数据, 评价结果}─────────│
    │                               │
    │── POST /api/ai-analyze───────→  代理转发到 AI API
    │←── {AI 分析结果}──────────────│
```

### 4.2 Socket.IO 长连接（服务器主动推送）

HTTP 只能客户端问、服务器答。但仿真需要**服务器每秒主动推数据**，这就用 Socket.IO：

```
前端 socket.js                   后端 simulation.py
    │                               │
    │──── 建立 WebSocket 连接 ──────→  连接保持，不挂断
    │                               │
    │──── emit('bind_session') ────→  join_room(session_id)
    │                               │
    │                               │  仿真线程每秒：
    │←── emit('simulation_data') ───│  {window_people, used_table, ...}
    │←── emit('simulation_data') ───│  {window_people, used_table, ...}
    │←── emit('simulation_data') ───│  ...
```

### 4.3 WebSocket vs HTTP 轮询

Socket.IO 支持两种传输方式：

| 方式 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **WebSocket** | 建立一个长连接，双向通信 | 延迟低，开销小 | 某些企业防火墙会拦截 |
| **HTTP Polling** | 客户端不断发 HTTP 请求模拟实时 | 穿透代理/防火墙 | 延迟高，开销大 |

我们的配置：`transports: ['websocket', 'polling']`，意思是**优先用 WebSocket，不行就自动降级到 Polling**。

### 4.4 CORS 跨域问题

**什么是 CORS？** 浏览器的安全策略规定：`http://localhost:5001` 的页面不能随便请求 `http://dashscope.aliyuncs.com` 的 API。后端需要在响应头里声明"允许谁来访问"。

我们的解决方案：
1. 后端 `app.py` 中配置允许的 origin 列表（`127.0.0.1:5001`、`localhost:5001`）
2. 对于 AI API（DashScope 不允许浏览器直接访问），后端做**代理转发**——前端请求自己的后端，后端再代发到 AI API

## 5. 实时数据是怎么跑起来的

### 5.1 完整数据流（从用户点击到图表更新）

```
用户点击"启动仿真"
    │
    ▼
index.js: handleStartSimulation()
    │
    ├─1. 生成 sessionId (UUID)
    │
    ├─2. socket.emit('bind_session', sessionId)  ← 先占座！
    │
    ├─3. await 150ms（等待服务端处理 bind_session）
    │
    └─4. startSimulation({...params, session_id})
          │
          ▼
    后端 app.py 启动仿真线程
          │
          ▼
    仿真线程每秒：
      计算新到达人数 → 分配窗口 → 处理打饭 → 分配桌子
          │
          ▼
    socketio.emit('simulation_data', {...}, room=session_id)
          │
          ▼
    socket.js 收到 'simulation_data' 事件
          │
          ├─ 数据校验（数组? 数字?）
          │
          └─ window.dispatchEvent(new CustomEvent('simulation:data', {detail: {...}}))
                │
                ▼
          index.js 监听到 'simulation:data'
                │
                ├─ updateWindowBarChart(windowPeople)
                ├─ updateTablePieChart(usedTable, remainingTable)
                └─ updateKPICards_(...)
                      │
                      ▼
                requestAnimationFrame → ECharts.setOption() → 图表刷新
```

### 5.2 为什么用 CustomEvent 桥接

`socket.js` 收到数据后，**不直接调用** `index.js` 里的函数。而是通过 `window.dispatchEvent(new CustomEvent(...))` 发一个自定义事件，`index.js` 来监听。

好处：
- **解耦**：`socket.js` 不需要知道 `index.js` 里有什么函数
- **可测试**：可以单独测试每个模块
- **可扩展**：以后加新模块只需监听同一个事件即可

同样的模式也用于主题切换：`theme.js` 发 `themeChange` 事件 → `index.js` 收到后更新图表颜色。

### 5.3 时序竞争问题（启动时第一秒数据丢失）

**问题**：如果先启动仿真再绑定 Socket.IO 房间，仿真线程可能在房间绑定完成之前就开始推送数据，导致第一秒数据丢失。

**解决**：前端**先生成 sessionId，先绑定房间，等 150ms，再发启动请求**。这样确保数据推送时房间已经就绪。

## 6. 图表是怎么画出来的

### 6.1 ECharts 初始化

`initECharts()` 函数用 `echarts.init(domElement)` 初始化 4 个图表：

| 图表 | DOM 容器 | 类型 | 显示内容 |
|------|----------|------|----------|
| 窗口柱状图 | `#windowBarChart` | bar（柱状图） | 各窗口当前排队人数 |
| 桌子饼图 | `#tablePieChart` | pie（饼图） | 已用/剩余桌子占比 |
| 窗口折线图 | `#windowLineChart` | line（折线图） | 各窗口排队人数随时间变化 |
| 桌子折线图 | `#tableLineChart` | line（折线图） | 桌子占用数随时间变化 |

### 6.2 图表更新策略

为了性能优化，图表更新不是每次都直接调用 `setOption()`，而是：

1. 数据到达 → 存入 `state.chartData`（缓存）
2. 调用 `requestChartRender(chartKey)` → 标记这个图表"需要更新"
3. 用 `requestAnimationFrame` 在**下一帧**统一刷新所有待更新的图表

这样即使一秒内收到多次数据，也只渲染一次，避免卡顿。

### 6.3 柱状图的特殊排序

柱状图的柱子不是按窗口编号排列的，而是按**正态分布排列**：
- 排队人数最多的窗口放中间
- 第二多的放左边，第三多的放右边
- 第四多的放左边第二，第五多的放右边第二
- 以此类推

这样看起来像一个"山峰"，直观展示排队分布。

### 6.4 图表颜色与主题联动

图表颜色从 CSS 变量（`--chart-series-1` 到 `--chart-series-6`）中读取，切换主题时 CSS 变量值改变 → `themeChange` 事件 → 图表重新读取颜色 → 图表变色。

## 7. 主题切换是怎么实现的

### 7.1 5 套主题

| 主题 ID | 名称 | CSS 文件 |
|---------|------|----------|
| `morandi` | 莫兰迪蓝（默认） | `theme-morandi.css` |
| `mint` | 清新薄荷绿 | `theme-mint.css` |
| `lavender` | 薰衣草紫 | `theme-lavender.css` |
| `coral` | 珊瑚橙 | `theme-coral.css` |
| `dark` | 深色模式 | `theme-dark.css` |

### 7.2 切换原理

1. `<body>` 上有一个 CSS class（如 `theme-morandi`）
2. 每个主题 CSS 文件定义该主题下的所有颜色变量
3. 切换主题 = 换 `<body>` 的 class + 换 `<link id="active-theme">` 的 href
4. 发 `themeChange` 事件 → 图表重新读取 CSS 变量 → 变色
5. 选择保存到 `localStorage`，下次打开页面自动恢复

## 8. KPI 仪表盘是怎么算的

仿真运行时，4 个 KPI 卡片实时更新：

| KPI | 显示元素 | 计算公式 |
|-----|----------|----------|
| 排队总人数 | `#kpiQueueTotal` | 所有窗口排队人数之和 |
| 平均等待时间 | `#kpiAvgWait` | `(总人数 / 窗口数) × 打饭时间`（秒） |
| 桌子占用率 | `#kpiTableUsage` | `已用桌子 / (已用+剩余) × 100`（%） |
| 吞吐量 | `#kpiThroughput` | `累计到达 / 已过秒数 × 60`（人/分钟） |

每个 KPI 还保留最近 12 个值的历史记录，比较最近 3 个值判断趋势：
- 增超过 2 → "↑ 上升"
- 减超过 2 → "↓ 下降"
- 否则 → "→ 稳定"

数字变化有 GSAP 滚动动画效果。

## 9. 动画和交互效果怎么做

所有动画在 `animations.js` 中统一管理。如果 GSAP 未加载，自动降级：

| 动画 | GSAP 实现 | CSS Fallback |
|------|-----------|--------------|
| KPI 数字跳动 | `gsap.to(el, {textContent: val})` | 直接赋值 `el.textContent = val` |
| 侧边栏折叠 | `gsap.to(sidebar, {width})` + 弹性缓动 | CSS `transition: width 0.3s` |
| 结果面板弹入 | `gsap.from(resultArea, {y, opacity})` | CSS `@keyframes slideUp` |
| Toast 通知 | GSAP 时间线 + 自动堆叠 | CSS `@keyframes toastIn` |
| 按钮涟漪 | 动态创建圆形元素 + GSAP 缩放淡出 | `transform: scale()` + `opacity` |

## 10. 我们遇到了哪些坑，怎么解决的

### 10.1 时序竞争（第一秒数据丢失）
**症状**：启动仿真后图表从第 2 秒才开始显示数据。
**原因**：仿真线程启动比 Socket.IO 房间绑定快。
**解决**：前端先绑定房间，等 150ms，再发启动请求。

### 10.2 CORS 跨域
**症状**：浏览器报 `blocked by CORS policy`，API 请求全部失败。
**原因**：`localhost` 和 `127.0.0.1` 被视为不同的域名。
**解决**：后端 CORS 列表同时包含两个地址。

### 10.3 AI API 调不通
**症状**：前端直接请求 DashScope API 报 CORS 错误。
**原因**：DashScope 不对浏览器开放 CORS。
**解决**：前端请求自己后端 → 后端代发到 DashScope（代理模式）。

### 10.4 Socket 断连
**症状**：某些网络下 WebSocket 连不上。
**原因**：企业防火墙拦截 WebSocket 协议。
**解决**：配置 `transports: ['websocket', 'polling']` 自动降级。

### 10.5 端口不一致
**症状**：前端请求全部 `ERR_CONNECTION_REFUSED`。
**原因**：后端默认端口 5001，前端配置还是 5000。
**解决**：统一使用 5001，并在 `config.js` 中配置。

## 11. 老师可能会问的问题（Q&A）

### Q1：前端和后端是怎么通信的？用了什么协议？
**A**：两种方式。普通的启动/停止操作用 HTTP POST 请求（fetch API），实时数据推送用 Socket.IO（优先 WebSocket，自动降级 HTTP Polling）。Socket.IO 是一个封装好的库，帮我们处理了连接管理、心跳、重连、降级等复杂逻辑。

### Q2：为什么要用 Socket.IO 而不是直接用 WebSocket？
**A**：Socket.IO 在 WebSocket 基础上提供了更多保障：自动重连、心跳检测、房间机制（可以只向特定 session 推送）、传输层降级（WebSocket 不通时自动切 Polling）。如果用裸 WebSocket，这些都要自己写。

### Q3：图表实时更新的性能怎么保证？
**A**：两个优化手段：(1) 用 `requestAnimationFrame` 合并同一帧内的多次数据更新，避免频繁操作 DOM；(2) ECharts 的 `setOption` 使用 `lazyUpdate: true` 和 `silent: true`，跳过不必要的布局计算。

### Q4：CustomEvent 是什么？为什么要用它？
**A**：CustomEvent 是浏览器原生的事件机制，可以自定义事件名和数据。我们用它在 `socket.js` 和 `index.js` 之间传递数据，两个模块不需要直接引用对方，降低了耦合。就像两个人通过对讲机通信，而不是直接喊话——换一个人来接听也不需要改发射端。

### Q5：5 套主题是怎么实现的？
**A**：使用 CSS 变量（`--chart-series-1` 等）。每个主题 CSS 文件定义一组变量值，切换主题就是换一个 CSS 文件。图表颜色从 CSS 变量中读取，所以主题一变图表颜色自动跟着变。选择保存到 `localStorage` 实现持久化。

### Q6：如果后端挂了，前端会怎样？
**A**：Socket.IO 会自动尝试重连（最多 5 次，间隔 1 秒）。API 请求有 10 秒超时，超时后会弹出 Toast 错误提示。如果 Socket 未连接，点击启动仿真会提示"实时通信未连接，请确认后端服务已启动"。

### Q7：前端怎么知道仿真结束了要显示什么数据？
**A**：调用 `POST /api/end-simulation`，后端返回一个 JSON，包含 `window_trend`（窗口历史趋势）、`table_trend`（桌子历史趋势）、`window_evaluation`（窗口体验评价，如"体验良好"或"体验较差"）、`table_evaluation`。前端拿到后更新折线图和结果面板。

### Q8：ECharts 图表的数据格式是什么？
**A**：柱状图和折线图的 x 轴是分类名/时间，y 轴是数值，数据格式为 `[value1, value2, ...]`。饼图的数据格式为 `[{name: '已使用', value: 30}, {name: '剩余', value: 70}]`。

### Q9：KPI 仪表盘的趋势是怎么判断的？
**A**：每个 KPI 保留最近 12 次的值，取最近 3 次比较：如果最近一次比 3 次前增加超过 2，显示"上升"；减少超过 2，显示"下降"；否则"稳定"。

### Q10：你们用了 ES6 模块，老浏览器怎么办？
**A**：`index.js` 开头有兼容性检查：`if (!window.Promise || !Array.prototype.map)`，不支持的浏览器会在控制台打印警告。现代浏览器（Chrome 61+、Firefox 60+、Edge 16+）都支持 ES6 模块。

### Q11：为什么 animations.js 和其他 JS 文件的写法不一样？
**A**：`animations.js` 用的是 IIFE（立即执行函数），其他文件用的是 ES6 模块。原因：(1) GSAP 的 ScrollTrigger 插件需要在全局注册；(2) 动画系统到处都要调用，挂到 `window.Animations` 上更方便；(3) 如果 GSAP 没加载，它会自动降级，不会因为 import 失败而报错。

### Q12：AI API 为什么要通过后端代理？
**A**：因为浏览器的同源策略（CORS）。DashScope API 没有对浏览器开放跨域访问，前端直接发请求会被浏览器拦截。通过后端代理：前端 → 自己的后端（同源，不触发 CORS）→ 后端代发到 DashScope（后端不受 CORS 限制）。

### Q13：启动仿真时那个 150ms 延迟是干什么的？
**A**：用来解决时序竞争。前端先发 `bind_session` 事件让后端加入房间，但网络+服务端处理需要时间。150ms 是一个安全余量，确保房间绑定完成后才启动仿真，避免第一秒数据丢失。150ms 对用户来说完全无感知。

### Q14：localStorage 里存了什么？
**A**：两样东西：(1) AI 配置信息（API URL、API Key、模型名称），存在 `simulation_ai_config` 键下；(2) 主题选择，存在 `simulation_theme` 键下。这样用户下次打开页面时，之前的配置还在。
